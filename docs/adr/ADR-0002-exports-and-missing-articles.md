# ADR-0002: Экспорт по запросу и обработка ненайденных артикулов

- Статус: Proposed
- Дополняет: [ADR-0001 — Обработка списка товаров для перефотографирования](./ADR-0001-photograf-selection-flow.md)

## Контекст

ADR-0001 определяет исключение подходящих товаров из текущего `arts.txt` и формирование результатов по складам. Фотографу нужны как полный экспорт складов, так и возможность сформировать файл только для выбранного склада. Также уточнена обработка артикулов, которых нет в товарной базе.

Важно различать товар, который найден в базе, но не имеет фотографии, и артикул, который не найден в базе. Отсутствие фотографии не должно лишать товар его складской принадлежности.

## Решение

- TXT-файлы по складам создаются только по явной команде фотографа: можно сформировать файл выбранного склада отдельно либо файлы всех складов. Автоматически сохранять или формировать эти результаты не нужно.
- Товары, найденные в базе, но не имеющие фотографии, остаются в обычном потоке обработки и в результате соответствующего склада. Для них не создается отдельный список только из-за отсутствия фотографии.
- Артикулы, не найденные в базе, обрабатываются отдельно от товаров без фотографии. Фотограф может по запросу выгрузить их в отдельный TXT-файл, удалить один такой артикул или удалить все ненайденные артикулы текущего списка.
- Массовое удаление должно затрагивать только артикулы, подтвержденно классифицированные как не найденные в базе; перед ним требуется подтверждение количества удаляемых артикулов.
- Удаление исключает записи только из текущего `arts.txt` и не меняет товарную базу. Подходящие товары по-прежнему удаляются по одному согласно ADR-0001.

## Последствия

- Создание складских файлов остается под контролем фотографа и не происходит автоматически; полный экспорт не обязателен для получения файла одного склада.
- Товары без фото не теряют складскую привязку и остаются в результирующем файле своего склада.
- Ненайденные артикулы можно передать отдельно для проверки и удалить выборочно либо одной операцией.
- Массовое удаление требует надежной серверной фильтрации по статусу «не найден в базе», а не доверия выбору на клиенте.
- Если исходный `arts.txt` заново выгружен из 1С во время обработки, перед записью необходимо защититься от перезаписи новой выгрузки устаревшим состоянием.

## Альтернативы

- **Автоматически формировать складские TXT после каждого изменения.** Отклонено: фотограф должен запускать экспорт явно.
- **Экспортировать только все склады одной командой.** Отклонено: фотограф должен иметь возможность передать на сборку товар только одного выбранного склада.
- **Выносить все товары без фотографии в отдельный список независимо от склада.** Отклонено: отсутствие фотографии не отменяет складскую принадлежность товара.
- **Удалять все записи без дополнительной проверки статуса.** Отклонено: массовое действие должно применяться только к артикулам, не найденным в базе.
- **Удалять артикулы из товарной базы.** Отклонено: обработка изменяет только текущий список `arts.txt`.

## Условие пересмотра

Пересмотреть решение, если понадобится автоматически отправлять результаты, сохранять прогресс между выгрузками из 1С, вести журнал решений или менять статус товара в базе.
