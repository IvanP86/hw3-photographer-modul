# ADR-0003: Реализация страницы фотографа на SOLID без DDD

- Статус: Proposed
- Дополняет: [ADR-0001 — Обработка списка товаров для перефотографирования](./ADR-0001-photograf-selection-flow.md)
- Дополняет: [ADR-0002 — Экспорт по запросу и обработка ненайденных артикулов](./ADR-0002-exports-and-missing-articles.md)

## Контекст

Для страницы фотографа выбран подход SOLID без DDD. Проект — легаси PHP/JS без Composer и сборки, поэтому реализацию нужно легко перенести в существующее приложение и не обременять лишними слоями. Поведение страницы и работа с файлами заданы ADR-0001 и ADR-0002.

## Решение

Реализовать страницу как небольшой PHP-модуль с ручным подключением классов:

- HTTP-контроллер отвечает за запросы, сессию, доступ, CSRF и HTML-ответ.
- Прикладной сервис реализует сценарии просмотра, удаления и экспорта.
- Отдельные интерфейсы задают границы доступа к `arts.txt`, каталогу товаров и экспортным TXT.
- Файловые и Bitrix-адаптеры реализуют эти интерфейсы; локальная разработка использует псевдоданные.
- Использовать простые структуры данных, не вводить DDD-слой, агрегаты, контейнер зависимостей или внешние пакеты.

Новый код должен оставаться совместимым с PHP 7.4. Удаление изменяет только текущий `arts.txt`; экспорт складских и ненайденных TXT выполняется по явной команде. Массовое удаление ограничено артикульными записями в секции «Не найдено в базе».

## Последствия

- Реализацию можно переносить в легаси-проект без Composer, сборки и новой инфраструктуры данных.
- Ответственности и границы интеграций достаточно разделены для проверки и замены локального адаптера на Bitrix.
- Сложные доменные правила не моделируются заранее; при существенном росте требований потребуется пересмотр структуры.
- Сохранение файла требует проверки версии исходника и безопасной замены, чтобы не затереть новую выгрузку из 1С.

## Альтернативы

- **Один PHP-скрипт.** Отклонено: быстрее начать, но HTTP, работа с файлами, Bitrix и экспорт быстро смешаются.
- **DDD.** Отклонено для текущего объёма: дополнительная доменная модель и слои увеличат стоимость переноса, не требуясь текущим правилам.
- **Полноценная слоистая архитектура с DI-контейнером и внешними библиотеками.** Отклонено: противоречит ограничениям легаси-переноса без Composer и сборки.

## Условие пересмотра

Пересмотреть решение, если появятся долговременные задания обработки, аудит решений, несколько источников списков или сложные правила доступа и обработки, требующие отдельной доменной модели.
